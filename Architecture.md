# Adventure Learning Architecture

## Purpose

If the **Adventure Learning Constitution** explains *why* Adventure
Learning exists, this document explains *how* it works.

The architecture translates philosophy into a repeatable process for
creating meaningful learning experiences.

------------------------------------------------------------------------

# The Learning Flow

``` text
Situation
    ↓
Anxiety
    ↓
Story
    ↓
Episodes
    ↓
Skills
    ↓
Confidence
```

Each step exists for a reason. Removing one weakens the learning
experience.

------------------------------------------------------------------------

# 1. Situation

Every Adventure Learning project begins with a real situation.

Examples:

-   Borrowing a parent's car
-   Dashboard warning light appears
-   Opening a confusing medical letter
-   Using AI for the first time

A situation answers:

> **What is happening?**

------------------------------------------------------------------------

# 2. Anxiety

Every meaningful situation contains uncertainty.

Examples:

-   I don't know what to do.
-   I'm afraid I'll make things worse.
-   I don't want to look foolish.

This is the design driver.

Ask:

> **What anxiety are we reducing?**

------------------------------------------------------------------------

# 3. Story

Stories answer:

> **Why should I care?**

The story creates emotional engagement and gives the learner a reason to
continue.

Stories motivate.

They do not replace instruction.

------------------------------------------------------------------------

# 4. Episodes

Episodes answer:

> **What happens next?**

Each episode removes one uncertainty.

Each episode teaches one meaningful action.

Episodes are reusable across multiple stories.

------------------------------------------------------------------------

# 5. Skills

Every episode should leave the learner able to do something.

Examples:

-   Check the oil
-   Find the owner's manual
-   Connect Android Auto
-   Ask AI to explain a document

Skills are the lasting outcome.

------------------------------------------------------------------------

# 6. Experience

Experience transforms information into confidence.

Every episode should include practical wisdom.

Examples:

-   Tony's Tips
-   Common mistakes
-   Reassurance
-   Warnings

Facts explain.

Experience builds confidence.

------------------------------------------------------------------------

# 7. Confidence

Confidence is never taught directly.

It emerges after repeated successful experiences.

Success is measured by capability, not memorization.

------------------------------------------------------------------------

# Author Workflow

When creating a new mission:

1.  Describe the situation.
2.  Identify the learner's anxiety.
3.  Define the desired capability.
4.  Create the story.
5.  Break it into episodes.
6.  Identify the skills.
7.  Add Tony's Tips and warnings.
8.  Review using the Adventure Learning Test.

------------------------------------------------------------------------

# Studio Responsibilities

The Studio should:

-   Hide technical complexity.
-   Guide the author through the workflow.
-   Reuse episodes and skills.
-   Generate mission structure automatically.
-   Publish with minimal effort.

Authors should think about helping people---not managing files.

------------------------------------------------------------------------

# Design Rule

Whenever a design decision is difficult, ask:

> Does this help someone move from uncertainty to confidence?

If yes, it belongs.

If not, reconsider it.
